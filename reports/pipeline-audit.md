# Lumvi Chat Pipeline Audit

Scope: read-only source audit of the current `shopify-variant-lookup` checkout. No code or tests were run for this audit. Every statement below is tagged `Read in code` when it describes a direct code fact, or `Inferred` when it draws a conclusion from code structure or absence of a call site. File links point to the cited source function/line.

## 1. Request Flow

1. **Widget bootstrap.** [Read in code] `static/widget.js` chooses the client ID from `window.LUMVI_CLIENT_ID`, the script's `data-client-id`, or `demo`, then sets `baseUrl` to `https://lumvi.net` ([widget.js](../static/widget.js#L14), [widget.js](../static/widget.js#L28)). It fetches `/api/config?client_id=...`, applies branding/position/icon/online state, and creates an iframe at `/widget?client_id=...` ([widget.js](../static/widget.js#L74), [widget.js](../static/widget.js#L217)). This file does not send chat messages; the iframe page does.
2. **Iframe state and first-party history.** [Read in code] `templates/chat.html` receives `CID` and display/lead configuration from the server; it creates or reuses `SESSION_ID` in `localStorage` under `lumvi_sid_${CID}` ([chat.html](../templates/chat.html#L1264), [chat.html](../templates/chat.html#L1302)). It stores rendered history in `localStorage` under `lumvi_history_${CID}`, keeping up to 40 entries ([chat.html](../templates/chat.html#L1276), [chat.html](../templates/chat.html#L1379)).
3. **Send.** [Read in code] `sendMsg()` trims input, prevents concurrent sends, renders the user message, adds it to local history and saves, then calls `_sendToAPI()` unless the widget is in its separate lead-form mode ([chat.html](../templates/chat.html#L1480)).
4. **HTTP request.** [Read in code] `_sendToAPI()` aborts any prior fetch, starts a 30-second timeout, and POSTs JSON to `/api/chat` with `{message, client_id, session_id, history}`; the submitted history is the last 20 `{role, content}` entries ([chat.html](../templates/chat.html#L1671), [chat.html](../templates/chat.html#L1682)).
5. **Route input and tenant data.** [Read in code] `blueprints.chat.chat()` sanitizes `message`, `client_id` (default `demo`), and `session_id`; it returns HTTP 400 if the sanitized message is empty ([chat.py](../blueprints/chat.py#L116)). It loads the tenant using `models.get_client_by_id(client_id)`, parses `branding_settings`, fetches active FAQs, then appends embedded Business Knowledge results ([chat.py](../blueprints/chat.py#L131), [chat.py](../blueprints/chat.py#L154)). **[Read in code]** The handler does not read `data['history']`; when AI is enabled it calls `models.get_recent_conversations(client_id, session_id, limit=15)` ([chat.py](../blueprints/chat.py#L393)). **[Inferred]** The widget-provided history is therefore transport-only for this route; the database history passed into the AI pipeline is scoped to the request's client and session.
6. **Route-level gates and helper call.** [Read in code] The route applies plan/quota checks, computes vertical and lead settings, handles the AI-disabled keyword lead path, and otherwise calls `_ai_helper.generate_response()` with message, combined FAQ/knowledge list, vertical, DB history, client ID, lead triggers, KB version, session ID, and recommendation-plan boolean ([chat.py](../blueprints/chat.py#L210), [chat.py](../blueprints/chat.py#L344), [chat.py](../blueprints/chat.py#L382)).
7. **Pipeline result to route JSON.** [Read in code] The helper returns a dict with a reply and method/confidence plus optional lead/handoff/action fields; the route logs the branch and builds a JSON response. Pipeline handoff/lead branches and normal AI branch differ in their keys ([chat.py](../blueprints/chat.py#L430), [chat.py](../blueprints/chat.py#L480), [chat.py](../blueprints/chat.py#L520), [chat.py](../blueprints/chat.py#L540)).
8. **Reply to widget.** [Read in code] The widget checks `d.success`, renders `d.response`, supplies `d.quick_replies` to `addBotMsg()`, saves the assistant turn in local storage, checks `d.request_human_handoff`, checks `d.confidence`, and starts its lead form if `d.trigger_lead_collection` is true ([chat.html](../templates/chat.html#L1700)).

Plain-text flow:

```text
embed script static/widget.js
  -> GET /api/config?client_id
  -> iframe GET /widget?client_id
  -> templates/chat.html creates/reuses local session ID and local history
  -> sendMsg()
  -> _sendToAPI() POST {message, client_id, session_id, history[-20:]}
  -> blueprints.chat.chat(): sanitize + tenant lookup + FAQs + Business Knowledge
  -> route quota / lead / AI gates
  -> AIHelper.generate_response(..., DB history[-15 turns], tenant inputs)
  -> state machines -> intent -> direct tool/action exit OR retrieval/RAG
  -> route logs, optional handoff/training/webhooks
  -> JSON response
  -> widget renders response/quick replies, stores local assistant turn
```

[Read in code] The flow sequence above is summarized from the cited widget, route, and orchestrator functions ([widget.js](../static/widget.js#L74), [chat.html](../templates/chat.html#L1671), [chat.py](../blueprints/chat.py#L116), [ai_helper.py](../ai_helper.py#L784)).

[Read in code] The iframe response uses a JSON `response` string for the visible answer; the current widget renderer does not render a structured product array from `/api/chat` ([chat.html](../templates/chat.html#L1534), [chat.html](../templates/chat.html#L1704)).

## 2. Pipeline Stages

**Runtime order in `AIHelper.generate_response()`**

1. [Read in code] **Empty-message gate:** returns `PipelineResult.empty_message()` before constructing context when the input is empty/whitespace ([ai_helper.py](../ai_helper.py#L784)).
2. [Read in code] **Preprocess:** collapse whitespace into `ctx.clean_message` ([ai_helper.py](../ai_helper.py#L830)).
3. [Read in code] **Session load/merge:** load persisted session only with both client and session IDs; compute regex/history memory; later dict values overwrite earlier ones in the merge ([ai_helper.py](../ai_helper.py#L840), [session_store.py](../services/session_store.py#L37)).
4. [Read in code] **Purchase-stage update:** detect a stage and advance by the configured stage order; it does not regress ([ai_helper.py](../ai_helper.py#L848), [constants.py](../constants.py#L161)).
5. [Read in code] **Email-capture state machine:** pending email capture handles decline, email, phone, retry, and retry exhaustion; these return before intent or retrieval ([ai_helper.py](../ai_helper.py#L858)).
6. [Read in code] **Handoff state machine:** accepts/declines an outstanding handoff offer or asks for contact information; returns before intent/retrieval where resolved ([ai_helper.py](../ai_helper.py#L899)).
7. [Read in code] **Escalation gate:** `check_escalation()` checks urgent billing signals, accumulated frustration, then multiple current-message frustration signals; on a match it returns an offer and persists session state ([ai_helper.py](../ai_helper.py#L1028), [escalation.py](../pipeline/stages/escalation.py#L62)).
8. [Read in code] **Response-cache read:** deferred until after handoff/escalation; cache reads and writes are skipped for messages `is_followup()` classifies as follow-ups ([ai_helper.py](../ai_helper.py#L1045), [retrieval.py](../pipeline/stages/retrieval.py#L56)).
9. [Read in code] **Poor-answer IDs and pending fixed-tool confirmation:** poor KB IDs load with failure falling back to an empty set; pending write tool info/confirmation/expiry may return before intent ([ai_helper.py](../ai_helper.py#L1078), [ai_helper.py](../ai_helper.py#L1090)).
10. [Read in code] **Intent:** run simple keywords, action keywords, tool keywords, prospect/sales signals, and conditional Gemini classification. Purchase stage can additionally coerce browsing/evaluating to lead status ([ai_helper.py](../ai_helper.py#L1210), [ai_helper.py](../ai_helper.py#L1237)).
11. [Read in code] **Intent short-circuits:** goodbye/gratitude, actions, and eligible tools return before FAQ retrieval; product search is plan-gated ([ai_helper.py](../ai_helper.py#L1250), [ai_helper.py](../ai_helper.py#L1280)).
12. [Read in code] **Pronoun short-circuit:** a message of up to three bare-pronoun tokens can return clarification without retrieval ([ai_helper.py](../ai_helper.py#L1410)).
13. [Read in code] **Query resolution and retrieval:** resolve follow-up context, split compound queries, embedding-search up to three subqueries where applicable, use BM25-only fallback if embeddings yield no candidates, optionally rewrite, hybrid-rerank, optionally cross-encoder rerank, then qualify by score and topic overlap ([ai_helper.py](../ai_helper.py#L1460), [retrieval.py](../pipeline/stages/retrieval.py#L72), [retrieval.py](../pipeline/stages/retrieval.py#L116), [retrieval.py](../pipeline/stages/retrieval.py#L182), [retrieval.py](../pipeline/stages/retrieval.py#L235), [retrieval.py](../pipeline/stages/retrieval.py#L295), [retrieval.py](../pipeline/stages/retrieval.py#L372)).
14. [Read in code] **Generation:** use FAQ-keyed cache, RAG generation if qualified and AI is configured, dynamic fallback if AI is configured but retrieval is not qualified, otherwise static fallback ([ai_helper.py](../ai_helper.py#L1700)).
15. [Read in code] **Post-generation:** parse `CLARIFY:`, apply guardrails, cache eligible result, record KB gap on IDK methods, append guarded lead nudge, persist session state, create handoff payload, and return `PipelineResult.to_dict()` ([ai_helper.py](../ai_helper.py#L1780), [generation.py](../pipeline/stages/generation.py#L391), [context.py](../pipeline/context.py#L170)).

## 3. Intent Classification

- [Read in code] Tier 1 is substring matching over `SIMPLE_INTENTS`: `greeting`, `gratitude`, `goodbye` ([constants.py](../constants.py#L13), [intent.py](../pipeline/stages/intent.py#L38)).
- [Read in code] Tier 2A scans action keyword maps and lead-trigger strings, returning `action` with one of `pricing_request`, `demo_request`, `meeting_request`, `contact_request` ([constants.py](../constants.py#L32), [intent.py](../pipeline/stages/intent.py#L53)). Contact request also uses regex pattern families in constants ([constants.py](../constants.py#L70)).
- [Read in code] Tier 2B scans `TOOL_KEYWORDS`; longest matching phrase wins. Registered keyword tool names are `lookup_order`, `cancel_order`, `check_availability`, `book_appointment`, `escalate_to_human`, `search_knowledge_base`, and `search_products` ([constants.py](../constants.py#L112), [intent.py](../pipeline/stages/intent.py#L96)).
- [Read in code] Tier 2.5 checks `PROSPECT_INFO_KEYWORDS`; pricing checks `GLOBAL_PRICING_KW`; vertical lead words come from `PERSONALITIES[vertical]['lead_keywords']` ([intent.py](../pipeline/stages/intent.py#L658), [constants.py](../constants.py#L23), [constants.py](../constants.py#L215)).
- [Read in code] Tier 3 asks Gemini for JSON with `intent` from `question|complaint|greeting|goodbye|gratitude|other`, plus `is_sales`, `is_lead`, and `confidence`; parse/model failure defaults to `question`, false sales/lead, confidence 0.3 ([intent.py](../pipeline/stages/intent.py#L537)). The combined result starts as `question`, confidence 0.5; when Gemini is skipped, that default remains after unmatched rules ([intent.py](../pipeline/stages/intent.py#L603)).
- [Read in code] `book_appointment` and `check_availability` set lead status. Keywords in `GLOBAL_PRICING_KW` set both lead and sales. Purchase-stage `browsing`/`evaluating` can later coerce lead true ([intent.py](../pipeline/stages/intent.py#L647), [ai_helper.py](../ai_helper.py#L1237)).
- [Read in code] Product questions land in `search_products` only if some literal keyword from its list matches; that list includes “do you sell”, “in stock”, “do you carry”, “what goes well with”, “recommend something”, and similar strings ([constants.py](../constants.py#L147)).
- [Inferred] Phrasing not caught by those product keywords, e.g. “is that available” or “how much is the large”, proceeds through lead/Gemini classification and potentially FAQ/RAG; the freshness regex in `tools.py` cannot help unless `search_products()` was already selected ([constants.py](../constants.py#L147), [intent.py](../pipeline/stages/intent.py#L585), [tools.py](../tools.py#L905)).
- [Read in code] `recommend_products` is a function/schema entry in `tools.py`, but is not a key in `TOOL_KEYWORDS`; `recommend_products()` itself is not called by `search_products()` intent dispatch ([tools.py](../tools.py#L1072), [constants.py](../constants.py#L112)).
- [Inferred] A no-match does not mean “ask the model to choose any registered tool”: the current orchestrator proceeds to retrieval/RAG unless Tier 3 or a rule returns a recognized action/tool ([ai_helper.py](../ai_helper.py#L1210), [ai_helper.py](../ai_helper.py#L1300)).

## 4. AI Helper

- [Read in code] `AIHelper` initializes the `google.genai` client when an API key is present; default model is `gemini-3.8-flash`, overridable by `GEMINI_MODEL` ([ai_helper.py](../ai_helper.py#L250), [ai_helper.py](../ai_helper.py#L269)). `Config.GEMINI_MODEL` also reads `GEMINI_MODEL` with the same fallback ([config.py](../config.py#L14)); `.env.example` documents the default.
- [Read in code] Provider selection is dynamic: `AI_PROVIDER` defaults to Gemini; a DB system setting can override it; OpenRouter is available, with Groq fallback on qualifying quota/auth errors ([utils.py](../utils.py#L50), [utils.py](../utils.py#L61), [utils.py](../utils.py#L281), [utils.py](../utils.py#L330)).
- [Read in code] General `utils.generate()` uses temperature `0.3`, max output `512`; Gemini and OpenRouter paths apply those settings ([utils.py](../utils.py#L50), [utils.py](../utils.py#L279), [utils.py](../utils.py#L338)). External configured-action calls, if invoked, use separate settings: temperature `0.1`, max 256 tokens ([agent_actions.py](../pipeline/stages/agent_actions.py#L153), [agent_actions.py](../pipeline/stages/agent_actions.py#L189)).
- [Read in code] The RAG prompt is built in `rag_generate_and_polish()` from vertical name, derived personality tone/polish hints, conversation context, resolved query, and the top five candidate Q/A entries. It instructs the model to answer only from those KB entries, be concise, avoid invention, and offer team contact for gaps ([generation.py](../pipeline/stages/generation.py#L240)).
- [Read in code] Personality is sourced from `PERSONALITIES`, with runtime tone/polish changes for frustration and sales context ([generation.py](../pipeline/stages/generation.py#L157)).
- [Read in code] The route extracts `bot_settings.system_prompt` into `vertical_system_prompt`, but I found no use of that local variable after assignment and no `system_prompt` input in `generate_response()` ([chat.py](../blueprints/chat.py#L355), [ai_helper.py](../ai_helper.py#L784)).
- [Inferred] Tenant `system_prompt` therefore does not appear to reach the generation prompt through this route. Tenant vertical does; tenant FAQs plus embedded Business Knowledge reach retrieval; contact fields are used in route-level lead responses, not the RAG prompt ([chat.py](../blueprints/chat.py#L355), [chat.py](../blueprints/chat.py#L382), [generation.py](../pipeline/stages/generation.py#L240)).
- [Read in code] Route supplies up to 15 stored conversation rows as alternating user/assistant messages; `build_context()` formats only the last six message records, truncating each content string to 300 characters. Query rewrite uses the last two records, each truncated to 120 characters ([conversations.py](../models/conversations.py#L173), [generation.py](../pipeline/stages/generation.py#L188), [retrieval.py](../pipeline/stages/retrieval.py#L135)).
- [Read in code] Retrieved FAQ and Business Knowledge records are merged into one `faqs_list`; retrieval returns candidates and generation includes at most five Q/A pairs ([chat.py](../blueprints/chat.py#L154), [generation.py](../pipeline/stages/generation.py#L240)).
- [Read in code] Fixed tool results are formatted into text by `pipeline/stages/intent.py` and returned as the turn response; they are not passed back into another generation call in `AIHelper.generate_response()` ([intent.py](../pipeline/stages/intent.py#L249), [ai_helper.py](../ai_helper.py#L1300)).
- [Read in code] Intent classification, rewrite, and cross-encoder share `ctx.call1_used` checks; RAG generation is a later call. The context comments describe a two-call budget, and the live code marks intent/rewrite/cross-encoder usage ([context.py](../pipeline/context.py#L115), [ai_helper.py](../ai_helper.py#L1230), [ai_helper.py](../ai_helper.py#L1540), [ai_helper.py](../ai_helper.py#L1578)).
- [Inferred] This is not a strict total-provider-call ceiling: long-conversation summarization is submitted separately in the background and calls generation; it is not visibly charged against `call1_used` ([ai_helper.py](../ai_helper.py#L1750), [generation.py](../pipeline/stages/generation.py#L418)).
- [Read in code] Retrieval thresholds start at vector 0.40, high confidence 0.65, medium 0.40; sales reduces these by 0.05. BM25 fallback uses its separate minimum score 0.5 ([context.py](../pipeline/context.py#L96), [ai_helper.py](../ai_helper.py#L1398), [ai_helper.py](../ai_helper.py#L194)).
- [Read in code] `utils.generate()` can log provider token usage only when `client_id` is supplied ([utils.py](../utils.py#L281), [utils.py](../utils.py#L316)). Stage calls shown in `intent.py`, `retrieval.py`, and `generation.py` call `_gemini_generate(model, prompt...)` without `client_id` ([intent.py](../pipeline/stages/intent.py#L564), [retrieval.py](../pipeline/stages/retrieval.py#L170), [generation.py](../pipeline/stages/generation.py#L301)).

**`search_products` details**

- [Read in code] `_catalog_search()` sends the full sanitized customer query to `commerce_adapters.search_inventory_cached()`; query max is 300 characters. It does not query a local products table ([tools.py](../tools.py#L955)).
- [Read in code] Shopify returns up to five product records and up to ten variants per product; the adapter flattens variants to `InventoryMatch` values ([commerce_adapters.py](../commerce_adapters.py#L238)). Tool output includes title, available, quantity, variant, options, price, compare-at price, product URL, description, and image URL ([tools.py](../tools.py#L995)).
- [Read in code] The tool caps requested `limit` at five; no separate Lumvi ranking stage sorts product matches. Adapter order is preserved, then variant option matching filters where possible ([tools.py](../tools.py#L966), [tools.py](../tools.py#L988)).

## 13. Extension Points and Risks

- **Product recommendations.** [Read in code] `recommend_products()` already wraps the live catalog lookup and has a plan flag in its schema, but current keyword routing does not include a `recommend_products` intent and the registry helpers have no discovered call from the live orchestrator ([tools.py](../tools.py#L1072), [tools.py](../tools.py#L1333), [constants.py](../constants.py#L147), [ai_helper.py](../ai_helper.py#L1300)). **[Inferred]** Lowest-risk path is to wire an explicit recommendation-intent branch into the existing fixed-tool path and retain the plan check/server-side tenant ID. Risk: accidental search/recommend ambiguity, existing `search_products` plan gating, and adding a model loop without tool/call limits.
- **Structured product cards.** [Read in code] `InventoryMatch` and `search_products()` already expose URL/image/price/options, while `templates/chat.html` has a product-card markup fragment and separately server-rendered featured-product UI ([commerce_adapters.py](../commerce_adapters.py#L35), [tools.py](../tools.py#L995), [chat.html](../templates/chat.html#L856), [chat.html](../templates/chat.html#L1138)). **[Inferred]** Lowest-risk path is additive: return structured product data alongside the existing response string, pass it through the route, then render via an explicit allowlisted card renderer. Risk: current formatter/route/widget only expect text; trust/escaping of product URLs/images; card list order and five-item limit; keeping accessible text fallback.
- **Product in focus.** [Read in code] Session JSONB can store additional fields without a schema change; there is no existing product-focus field ([sessions.py](../models/sessions.py#L68), [session_store.py](../services/session_store.py#L160)). **[Inferred]** Lowest-risk path is a session-scoped product ID/variant key stored with an explicit expiry/update/clear policy and passed as context only for follow-ups. Risks: ambiguous “it/that” resolution, stale focus after browsing another product, cross-session leakage if keyed incorrectly, and cache keys that omit focus.
- **Prompt/knowledge controls.** [Read in code] The route extracts a tenant custom system prompt but does not pass it to the helper; generation prompt is assembled in `rag_generate_and_polish()` ([chat.py](../blueprints/chat.py#L355), [generation.py](../pipeline/stages/generation.py#L240)). **[Inferred]** A future prompt change belongs at that prompt boundary, with explicit precedence rules for retrieved data vs instructions and tests for all generation/fallback paths.
